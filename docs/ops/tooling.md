# Operator tooling (`tools/ops/`)

The repository ships its operator scripts under `tools/ops/`. Every host-specific location is read from an environment variable or a command-line option (`tools/ops/opsenv.py` for Python, `tools/ops/OpsEnv.ps1` for PowerShell, and `${ARCANECORE_*}` variables for Bash), so nothing in the tree names a machine or a user. When a required variable is unset and no command-line override is given, the script stops with a message naming the variable and this page.

## Environment variables

| Variable | Purpose |
|---|---|
| `ARCANECORE_LIVE_PROFILE` | The live server profile directory (the one that holds `appsettings.json`, `auth.db`, `characters.db`, `world.db`, and `qa/report.json`). |
| `ARCANECORE_LIVE_ROOT` | Fallback alias for `ARCANECORE_LIVE_PROFILE` when `ARCANECORE_LIVE_PROFILE` is unset. |
| `ARCANECORE_LIVE_HOME` | The local live install root used by `tools/ops/live/` and `tools/ops/diag/attach-debugger.ps1`: `bin/` (the daemons run from here), `logs/` (one file per daemon, `world.debug.jsonl` or `world.debug.log` and `realm.debug.jsonl` or `realm.debug.log` by the effective `Logging:ArcaneCore:Format`, which `launch-daemon.ps1` gives each daemon; `win32-debugger.log`), `snapshots/` (a `bin-<stamp>` copy per redeploy) and `dumps/`. |
| `ARCANECORE_CLUSTER_LINK_SECRET` | The gateway link secret (at least 16 characters) that `tools/ops/live/start-cluster.ps1 -Gateway` puts into the supervisor console's environment (`-LinkSecret` is the alternative). No default; never printed. |
| `ARCANECORE_LANES_ROOT` | The root directory that holds lane worktrees and operator output directories (`_deploy`, `_diag`, `_wf`, `_plan`), and the build-slot files `slot-locks/` and logs `slot-logs/` of `tools/ops/ci/run-in-slot.ps1`. |
| `ARCANECORE_DEPLOY_ROOT` | Directory for deploy artifacts and per-run deploy logs (defaults to `<ARCANECORE_LANES_ROOT>/_deploy`). |
| `ARCANECORE_DATA_ROOT` | Directory holding extracted build-5875 client data (`terrain-5875` and `client-dbc-5875`). |
| `ARCANECORE_TERRAIN_DIR` | Explicit override for the extracted `.map`/`vmaps`/`mmaps` directory (defaults to `<ARCANECORE_DATA_ROOT>/terrain-5875`). |
| `ARCANECORE_DBC_DIR` | Explicit override for the build-5875 DBC directory (defaults to `<ARCANECORE_DATA_ROOT>/client-dbc-5875`). |
| `ARCANECORE_REFS_ROOT` | Root directory holding reference checkouts and SQL dumps (`mangos-classic`, `vmangos`, `classic-db`). |
| `ARCANECORE_MANGOS_CLASSIC_REF` | Explicit override for the `mangos-classic` checkout (defaults to `<ARCANECORE_REFS_ROOT>/mangos-classic`). |
| `ARCANECORE_VMANGOS_REF` | Explicit override for the `vmangos` reference checkout (defaults to `<ARCANECORE_REFS_ROOT>/vmangos`). |
| `ARCANECORE_WOTLK_REF` | Optional 3.3.5a (`wotlk`) reference checkout path for cross-version comparison tools. |
| `ARCANECORE_CLASSICDB_DUMP` | Explicit override for the ClassicDB SQL dump (defaults to `<ARCANECORE_REFS_ROOT>/classic-db/Full_DB/ClassicDB_1_12_1_z2815.sql.gz`). |
| `ARCANECORE_GH_REPO` | GitHub `owner/repo` slug queried by CI and RSI scripts (defaults to `Krilliac/ArcaneCore`). |
| `ARCANECORE_SONDER_MCP_URL` | Optional endpoint URL for the local Sonder MCP offload service. |
| `ANTHROPIC_API_KEY` | Anthropic API key used by `tools/ops/llm/*` (read from the environment or `HKCU\Environment`; never logged). |


### Placeholders used in the documents

Documents name host locations with placeholders instead of real paths. They are not shell syntax: replace each with your own directory. Where a variable exists, scripts read it; otherwise the script's own default or parameter applies.

| Placeholder | Meaning | Variable |
|---|---|---|
| `<lanes-root>` | Directory holding lane worktrees, `_deploy`, `_logs` and the slot files | `ARCANECORE_LANES_ROOT` |
| `<deploy-root>` | Deploy artifacts and per-run deploy logs | `ARCANECORE_DEPLOY_ROOT` |
| `<data-root>` | Extracted build-5875 client data (`terrain-5875`, `client-dbc-5875`) | `ARCANECORE_DATA_ROOT` |
| `<refs-root>` | Reference checkouts and SQL dumps (`vmangos`, `mangos-classic`, `classic-db`) | `ARCANECORE_REFS_ROOT` |
| `<live-home>` | Local live install root (`bin/`, `logs/`) | `ARCANECORE_LIVE_HOME` |
| `<live-profile>` | Live server profile directory | `ARCANECORE_LIVE_PROFILE` |
| `<wow-client-dir>` | The 1.12.1 client folder | `ARCANECORE_TEST_CLIENT_DIR` |
| `<work-dir>` | A scratch directory outside the repository | fixed in the script or chosen per run, no variable |
| `<continuation-checkout>` | A local checkout used to continue earlier work | no variable |
| `<client-acceptance-checkout>` | A clean checkout used for a real-client acceptance run | no variable |
| `<sweep-root>` | The coordination directory of one live-sweep fleet run | no variable |
| `<server-zero-run>` | A MaNGOS Zero extraction directory (`maps`, `vmaps`, `mmaps`, `dbc`) | no variable |
| `<terrain-tools-dir>` | The extractor tools directory passed as `-ToolsDir` to `tools/terrain/build-terrain-data.ps1` | script parameter |
| `<re-research-root>` | A private clean-room research notes directory | no variable |
| `<claude-home>` | The assistant's per-user configuration directory | no variable |

Paths fixed inside a script (the default dump of `tools/content/refresh-world-content.ps1`, the slot script of `tools/ops/ci/repeat-test.ps1`) are not controlled by these variables.

## Local live server (`tools/ops/live/`)

The local live server runs Debug builds of Realm and World from `<ARCANECORE_LIVE_HOME>/bin`, each in its own console, started in `ARCANECORE_LIVE_PROFILE`. Typical cycle: build a worktree (Debug), `redeploy.ps1` from it, then `livecheck.ps1`, `tools/ops/diag/server-status.ps1` and `tools/ops/diag/attach-debugger.ps1` alongside.

| Script | Live server impact | Purpose and usage |
|---|---|---|
| `tools/ops/live/LiveEnv.ps1` | Read-only | Dot-sourced helpers: `Resolve-LiveHome`, `Resolve-LiveProfile` (parameter, else `ARCANECORE_LIVE_HOME` / `ARCANECORE_LIVE_PROFILE`, else a stop naming the variable), `Get-LiveDaemon` (the one running Realm or World process; refuses to guess between several), `Get-LiveLogFormat` (the effective `Logging:ArcaneCore:Format`: the `Logging__ArcaneCore__Format` environment value, else the profile's `appsettings.json`, else the legacy inference from the `Enabled` flags when `Format` is unset, else `Json`), `Get-LiveDaemonLogPath` (`<LiveHome>/logs/<role>.debug.jsonl` or `.log` by that format), `Set-LiveDaemonLogEnvironment` (gives the role its own file: with `Logging:ArcaneCore:Format` set it sets `Logging__ArcaneCore__File__Path` to `<role>.debug.<ext>` and removes `Logging__ArcaneCore__Json__Path`; with it unset it sets `File__Path` to `<role>.debug.log` and, only when the legacy `Logging:ArcaneCore:Json:Enabled` is visibly on, `Json__Path` to `<role>.debug.jsonl`) and `Get-LiveLogFallback` (fallback files written since a time; see below). |
| `tools/ops/live/start-single.ps1` | **Starts the live server** (not with `-Plan` / `-WhatIf`) | Realm, then World, each in its own console through `launch-daemon.ps1` (identical diagnostics, log paths, `ARCANECORE_LIVE_SERVER=1`, GC settings), each awaited until the process is alive and its port (the profile's `Auth:Port` / `World:Port`, or `-AuthPort` / `-WorldPort`) listens; then a status window (`server-status.ps1`, always read-only: `-Supervise` is refused, because that window restarts only from the profile's `standard-processes.json`; use `start-cluster.ps1` for restarts) and a debugger window (`attach-debugger.ps1` with both PIDs). Refuses when a daemon runs or a port is in use. `-NoStatus`, `-NoDebugger`, `-Diagnostics`, `-GCHighMemPercent`, `-StartTimeoutSec`. Every window title carries the detected build. `-Plan` prints each process, command line, environment (secrets masked) and wait. |
| `tools/ops/live/start-cluster.ps1` | **Starts the live server** (not with `-Plan` / `-WhatIf`) | `ArcaneCore.World` as the cluster host supervisor (`launch-daemon.ps1 -ClusterSupervisor`, log `logs/supervisor.debug.*`) with the realm and one combined world as `Cluster__Supervisor__Processes__<key>__...` environment variables (children: own log `logs/<key>.debug.*`, `Console=-ChildConsole` (Merged), `--Cluster:Supervisor:Enabled=false` for the world, heartbeat file `-HeartbeatPath`, default `logs/world.heartbeat`). `-Gateway` adds `ArcaneCore.Gateway` (`-GatewayPort`) and makes the world a gateway worker (`-WorkerPort`, `-WorkerAddress`, fencing on; `-MapWorker` sets `Cluster:Node:Role`); the link secret comes from `ARCANECORE_CLUSTER_LINK_SECRET` or `-LinkSecret`, only into the supervisor console's environment. `-HangTimeoutSeconds` (0 or 30-3600), `-HangCapture None|Stacks|Dump` (default Dump, `-HangCaptureTimeoutSeconds` 1 to 3600, default 300; `-Plan` warns when Dump is chosen with less than 120): evidence taken before the supervisor kills a hung world; dumps go to `<LiveHome>/dumps` (the existing `*.dmp` caps apply), stack reports to `logs/hangstacks` (not trimmed). The crash-dump variables of the supervisor console reach every child, all with the World pattern `world-%p-%t.dmp`: the pid tells them apart. Status window without `-Supervise`; debugger in watch mode (`attach-debugger.ps1 -SupervisorPid`, children only, never the supervisor). A child that exits while it starts is relaunched by the supervisor and the launcher waits for the next process. `-ChildConsole Window` gives a child its own console window, but the supervisor still redirects the child's input, output and error in every mode, so a child's own crash and fault dialogs (which need all three unredirected) never open; heartbeats and the hang watch are unaffected. Instead, with `Diagnostics:CrashDialog` on in the children (`Diagnostics__CrashDialog=true` in the supervisor console reaches them), a child that crashes on an unhandled exception, an unobserved-task termination or a watchdog FailFast writes its `crash-report.*.txt` next to its executable without any box, and the supervisor opens a crash dialog itself, on its own unredirected console desktop, when its own `Diagnostics:CrashDialog` is on and a child exits unexpectedly with a nonzero code (not a drain or stop it asked for, exit code 0 or a restart request); a child the supervisor ends after a hang gets a box too. It names the child, pid, exit code, the hang length and capture when there was one, and what the supervisor does next, and shows the child's newest report written since that child started (or says none was found, without naming a cause). One box at a time, never delaying a restart; a crash during a requested drain shows none ([the crash dialog](invariants.md#the-crash-dialog)). The new-fault dialog (`Diagnostics:FaultDialog`) still does not exist for children. The supervisor console's environment, the link secret included, also reaches the hidden diagnostics sidecar and `dotnet-counters` and appears in full dumps; in cluster mode the sidecar collects counters from the supervisor, not the world child; `MinClusterProcesses` equals the child count with `StopWhenBelowMinimum`, so a supervisor that gives up on a crash-looping gateway stops the whole cluster. Same refusals, `-Plan`, `-NoStatus`, `-NoDebugger` and window titles as `start-single.ps1`; the debugger warning (an exception-heavy child is slowed per exception; with `-HangCapture Dump` a dump request for a debugger-stopped child can wait up to `-HangCaptureTimeoutSeconds` before the kill) is in the script help. Not started: a standby worker or several workers (one characters writer lock per realm). |
| `tools/ops/live/LiveLaunch.ps1` | Read-only (`Start-LiveWindow` is the only function that starts a process) | Dot-sourced by the launchers and `launch-daemon.ps1`: `Get-LiveBuildConfiguration` (`Debug`, `Release`, `Mixed` or `unknown` for a bin directory, from each `ArcaneCore.*.dll`'s `DebuggableAttribute` (the optimizer bit decides) or `AssemblyConfigurationAttribute`, read with `System.Reflection.Metadata` without loading the assembly), window titles, secret masking, plan and wait helpers. |
| `tools/ops/live/launch-daemon.ps1` | **Starts a live daemon** in the current console | Starts `ArcaneCore.<Role>.exe` from `<LiveHome>/bin` in the profile directory with QuickEdit off, `DOTNET_ENVIRONMENT=Development`, `ARCANECORE_LIVE_SERVER=1` (the marker that keeps the map feed's packet tools off the live server, which runs as Development; [map feed](../areas/map-feed.md#packet-tools)), `NO_COLOR` removed, the role's own log path (`<LiveHome>/logs/<role>.debug.jsonl` or `.log` by the effective format, set through the environment so it overrides the profile's `appsettings.json`; whether the file is on stays the profile's `Enabled` choice) and `DOTNET_GCHighMemPercent` (default 97, both roles). `-Diagnostics Max` (default; `Standard` adds nothing) also sets crash-dump, hang-stack and diagnostic-option variables, starts a hidden `diagnostics-sidecar.ps1` (counters CSV, retention caps) and prints what is active ([live diagnostics](live-diagnostics.md)). Usage: `pwsh -NoExit -File tools/ops/live/launch-daemon.ps1 -Role <Realm\|World> [-LiveHome <dir>] [-Profile <dir>] [-GCHighMemPercent 97] [-Diagnostics Standard\|Max] [-DumpType Full\|Heap] [-HangStackIntervalSeconds 60] [-MaxDumpFiles 3] [-MaxDumpGB 30] [-MaxHangStackFiles 500] [-MaxHangStackMB 200] [-MaxCountersFiles 48] [-MaxCountersMB 2048]`. |
| `tools/ops/live/LiveDiagnostics.ps1`, `diagnostics-sidecar.ps1` | Read-only helpers / **starts a hidden companion process** (stops only its own collector, by process id) | Dot-sourced plan, environment, retention and counters-argument functions for `-Diagnostics`, and the per-daemon sidecar that `launch-daemon.ps1` starts; see [live diagnostics](live-diagnostics.md). |
| `tools/ops/live/redeploy.ps1` | **Touches live server** (plans first; then nothing, a hot apply through the World's control pipe, or the hard restart: Ctrl-C stops World then Realm, copies binaries, optionally swaps `world.db`, restarts both at AboveNormal); `-Plan`/`-WhatIf` is read-only | Plans with `RedeployPlan.ps1` ([redeploy.md](redeploy.md)): compares the worktree with the deploy record `<LiveHome>/bin/arcanecore-deploy.json` (deployed SHA, uncommitted paths, configuration fingerprint, module hashes), the profile's configuration and the module directory, and picks `None`, `Hot` (live config keys, `-ContentTables` that `.reload` supports, allowlisted hot modules: `.reload`/`.hotmodule` over the control pipe), `Restart` or `Blocked` (exit 2). A hot path that is unavailable falls back to the restart; a change the World rejects stops with exit 3. The restart snapshots `<LiveHome>/bin` to `snapshots/bin-<stamp>`, copies both Debug builds from `-Src` (default: the worktree the script is in; it must be built) and changed approved modules, and with `-WorldDbSwap <file>` puts a refreshed world database in place while the World is stopped (the target is the Sqlite `Data Source` of `Database:World:ConnectionString` in the profile's `appsettings.json`, or `-WorldDb`; an empty target is refused) (old file and its `-wal`/`-shm` kept as `world.db.bak-<stamp>`, copy hash-checked). After the start it fails if either daemon's log name was taken by another writer (a fallback file written since the start), then writes the deploy record. Usage: `pwsh -NoProfile -File tools/ops/live/redeploy.ps1 [-Src <worktree>] [-Plan\|-WhatIf] [-Json] [-ForceRestart] [-ContentTables <names>] [-WorldDbSwap <world.db> [-WorldDb <target>]] [-LiveHome <dir>] [-Profile <dir>] [-Diagnostics Standard\|Max]` (the level goes to both restarted daemons). |
| `tools/ops/live/RedeployPlan.ps1` | Read-only (the hot-apply functions send commands only when `redeploy.ps1` calls them) | Dot-sourced: the planner (`Get-RedeployPlan`, pure; `Get-LiveRedeployPlan` gathers its inputs), the deploy record (`Read-`/`Write-DeployRecord`), the configuration fingerprint, and the control-pipe client (`Connect-WorldControl` checks the serving PID, `Invoke-WorldControlCommand`, `Invoke-HotReloadStep`, `Invoke-HotModuleStep`, `Invoke-HotRedeploy`). |
| `tools/ops/live/livecheck.ps1` | Read-only | One-shot health read of the world's log, `logs/world.debug.jsonl` or `.log` (either format is read; warning when a fallback file was written in the window) since `-Since` (UTC, default 15 min ago): startup markers, level counts, distinct FAIL/CRIT/exception lines, first-chance crash-report count, top WARN lines (numbers folded), tick health and daemon process state. Usage: `pwsh -NoProfile -File tools/ops/live/livecheck.ps1 [-Since 'yyyy-MM-dd HH:mm'] [-LiveHome <dir>]`. |


A log file has one writer (`RollingFileWriter` locks `<file>.lock`). A daemon that finds its configured log already owned writes `<name>.<process>.<ext>` instead (for example `world.debug.ArcaneCore.Realm.jsonl`; then `<name>.<process>.<pid>.<ext>`) and says so once on stderr. Such a file in `logs/` means two processes were configured with one path: `livecheck.ps1` warns about it and `redeploy.ps1` fails on it.

## Diagnostics (`tools/ops/diag/`)

| Script | Live server impact | Purpose and usage |
|---|---|---|
| `tools/ops/diag/attach-debugger.ps1` | **Attaches a Win32 debugger** to Realm and World (never breaks in; every event is continued; KillOnExit off, so closing the console detaches) | Logs native exceptions, breakpoints, process exits with exit codes, and a count of CLR first-chance exceptions (the first 10, then every 500th) to `<LiveHome>/logs/win32-debugger.log`. It sees only exception code `0xE0434352`: name the CLR types with `exception-probe`. Usage: `pwsh -NoExit -File tools/ops/diag/attach-debugger.ps1 [-RealmPid <pid>] [-WorldPid <pid>] [-LogPath <file>] [-LiveHome <dir>]` (PIDs default to the running daemons). While attached, every debug event (thread start or exit, DLL load, first-chance exception) stops the whole daemon until the script continues it. Each debug loop continues its event at once and only enqueues its log line; the console and the log file are written by separate threads from bounded queues that drop (and count: "N lines dropped") when full, so a debugger console that stalls (a selection in it, the machine paging) does not stall the target. An exception-heavy target is still slowed by one whole-process stop per exception (about 0.2 ms each). Watch mode for a cluster supervisor: `-SupervisorPid <pid> [-PollSeconds <n>]` attaches to every `ArcaneCore.*` child of that process but never to the supervisor itself (a stopped supervisor stops reading its merged children's output), polls for new children (a relaunched child has a new PID) and attaches to them too, ends when the supervisor and everything attached are gone; `-WindowTitle` replaces the console title. `tools/ops/live/start-cluster.ps1` uses it. |
| `tools/ops/diag/exception-probe/` | Read-only (an EventPipe session; the target keeps running) | Prints, for a running daemon, how often each exception type + message was thrown over `seconds` and which method caught it, including types the crash handler keeps out of the log (cancellations, socket errors). Not in `ArcaneCore.slnx`. Usage: `dotnet run --project tools/ops/diag/exception-probe -- [pid\|World\|Realm] [seconds=60]`. |

### Read-differently-than-it-does audit

`tests/ArcaneCore.World.Tests/Architecture/ReadsDifferentlyAuditTests.cs` parses `src/` with Roslyn and lists four constructs that commonly read differently from what they do: **RB001** `is not A or B` / `is not A and B` / `is not A or not B` (`not` binds only to `A`, and `or not` is not De Morgan's `not (A or B)`; only `is not A and not B` is spared), **RB002** an explicit float, double or decimal to integer cast in packet and serialization code (`ArcaneCore.Protocol`, `Net`/`Packets` directories and namespaces, files named `*Packet*`; the cast truncates where rounding is often meant; a cast of a direct `Round`/`Floor`/`Ceiling`/`Truncate` call is exempt), **RB003** `??` beside an unparenthesized arithmetic, comparison, logical or `is` operator (including `is null`, `is not null`, `is { }`), **RB004** `async void` that is not an event handler. Every hit that exists is in `tests/ArcaneCore.World.Tests/Architecture/ReadsDifferentlyBaseline.txt` (`RULE | file | member | snippet | reason`, one line per occurrence); a new hit fails the test until it is fixed or added there with its reason, and a baseline line whose construct is gone fails it too. Set `ARCANECORE_READS_DIFFERENTLY_DUMP=<file>` for a run to write the current hits as baseline lines. The test also fails when a parsed file has a syntax error (C# newer than the pinned Roslyn), and counts async lambdas whose delegate type cannot be resolved with the unresolved casts. Limits: code in `#if` branches whose symbols are not defined by default is not parsed, and source-generator output is not seen.
