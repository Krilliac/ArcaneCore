# Vendors and trainers (build 5875)

The NPC service uses the existing inventory, skills and talent systems. `<refs-root>` was read only; no reference code or data was copied.

## Delivered

| Area | Behavior and read-only reference |
| --- | --- |
| Vendor list and purchase | `CMSG_LIST_INVENTORY` sends visible `npc_vendor` rows first, then shared `npc_vendor_template` rows selected by `creature_template.VendorTemplateId`, each ordered by slot. Compact one-based slots, stock, price, durability and BuyCount use the same rules for both. Empty lists include a zero error byte. The list and purchases share the first 128 visible rows; a row beyond that limit cannot be bought by forging either item-buy opcode. Purchase also checks vendor, stock, reputation, money and capacity. Vanilla list items have no extended cost. vmangos caps the packet at 128 but its item-id purchase search does not enforce that cap; ArcaneCore closes that gap. `<refs-root>\vmangos\src\game\ObjectMgr.cpp:10780-10860`; `<refs-root>\vmangos\src\game\Objects\CreatureDefines.h:624`; `<refs-root>\vmangos\src\game\Handlers\ItemHandler.cpp:688-779`; `<refs-root>\vmangos\src\game\Objects\Player.cpp:18316-18508`. |
| Range, refusals and walking vendors | Every vendor request uses the shared NPC interaction check: alive, not hostile or in combat, selectable, reputation above Unfriendly, and within `INTERACTION_DISTANCE` (5 yd) plus both bounding radii in 3D, measured between the player's last reported position and the creature's position on its spline at the last map update (vmangos `Player::CanInteractWithNPC`, `Objects/Player.cpp:2468-2526`; `Objects/ObjectDefines.h:24`). A refused list, sale or buyback sends `SMSG_SELL_ITEM` result 3 (`SELL_ERR_CANT_FIND_VENDOR`), which the 1.12.1 client shows as "That merchant doesn't like you."; a refused purchase sends `SMSG_BUY_FAILED` result 5, "too far away" (`Handlers/ItemHandler.cpp:448-452,618-623,704-710`; `Objects/Player.cpp:18368-18374`; client mapping `<re-research-root>\protocol\client-error-codes.md`, "Vendor"). Neither core sends buy result 4. There is no position extrapolation or extra margin. Listing the inventory (and gossip with the vendor) stops a wandering or waypoint vendor for 180 s, as in vmangos, so it stays in range while its window is open; see the interaction pause in [creature movement](creature-movement-spawns.md). A click on a vendor that is still walking can still be refused if the server's last position for the running player is behind what the client shows; vmangos behaves the same. |
| Stock | Each creature GUID has its own limited item count. A purchase subtracts `BuyCount * count`; each `incrtime` interval adds `BuyCount` up to `maxcount`. Unlimited rows appear as `0xFFFFFFFF`. `<refs-root>\vmangos\src\game\Objects\Creature.cpp:3429-3505`; `<refs-root>\vmangos\src\game\Handlers\ItemHandler.cpp:768`. |
| Prices | Vendor list, purchase and trainer prices use single-precision `uint32(base * reputationDiscount + 0.5f)`. `IPlayerReputation` supplies the discount; absent service means 1.0. `<refs-root>\vmangos\src\game\Handlers\ItemHandler.cpp:747-765`; `<refs-root>\vmangos\src\game\Objects\Player.cpp:18442-18445`; `<refs-root>\vmangos\src\game\Handlers\NPCHandler.cpp:112-119,306-315`. |
| Sell and buyback | Selling pays `SellPrice * count`, scaled by the expendable charges left (the first item spell with negative template charges) and less the undiscounted repair cost of lost durability (`uint32(lost * DurabilityCosts multiplier * DurabilityQuality factor)`, at least 1 copper; a cost above the price leaves 1 copper; a damaged item without a cost row cannot be sold, `ItemHandler.cpp:523-575`); the payout is capped at the wallet's room, and the paid amount is the buyback price. Twelve buyback slots carry price and timestamp update fields. A full list replaces the oldest. Buyback charges its stored price; sale and buy failures use the vanilla result packets. Buyback is session-only. `<refs-root>\vmangos\src\game\Handlers\ItemHandler.cpp:442-645`; `<refs-root>\vmangos\src\game\Objects\Player.cpp:11425-11469`. |
| Repair | `DurabilityCosts.dbc` selects an item-level/subclass multiplier and `DurabilityQuality.dbc` selects `(quality + 1) * 2`. Base cost is `uint32(lost * multiplier * qualityFactor)`; reputation then rounds with `+ 0.5f`, minimum one copper. Repair-all traverses equipment, backpack and equipped bags with their contents, excluding bank, buyback and keyring. An unaffordable item stays broken. Guild-bank payment is absent. `<refs-root>\vmangos\src\game\Objects\Player.cpp:4900-4977`. |
| Trainers | The list greys known spells, marks unmet level, skill, rank, class or race requirements red, and marks an exhausted first primary profession rank green-disabled. Purchase rechecks requirements and sends `SMSG_TRAINER_BUY_SUCCEEDED` or `SMSG_TRAINER_BUY_FAILED` (unavailable 0, money 1, skill 2). Class, pet, mount and profession trainer metadata is checked. `<refs-root>\vmangos\src\game\Objects\Player.cpp:4234-4299`; `<refs-root>\vmangos\src\game\Handlers\NPCHandler.cpp:97-139,141-342`; `<refs-root>\vmangos\src\game\Objects\Creature.cpp:1523-1569`. |
| Talent reset | The existing talent service owns class-trainer gossip, wipe confirmation, one-gold first reset, later five-gold multiplier steps, cap and 30-day decay. `<refs-root>\vmangos\src\game\Objects\Player.cpp:4030-4072,4075-4140,8260-8267`; see [talents](talents.md). |
| Bank | A banker opens the bank and inventory moves recheck access. Slot purchase uses the next `BankBagSlotPrices.dbc` row and persists `bank_bag_slots` with money (Characters schema v21). Failed purchase sends `SMSG_BUY_BANK_SLOT_RESULT` as one `u32`: too many 0, insufficient funds 1, not banker 2; success has no reply. `<refs-root>\vmangos\src\game\Handlers\ItemHandler.cpp:872-909`; `<refs-root>\vmangos\src\game\Objects\Player.cpp:14661-14664,16401-16404`; `<refs-root>\vmangos\sql\characters.sql:74`; `<refs-root>\wow_messages\wow_message_parser\wowm\world\item\smsg_buy_bank_slot_result.wowm:3-12`. |

## Configuration and limits

`NpcServices` accepts developer-supplied build-5875 DBC paths for durability costs/quality, bank bag prices and skill line abilities. Missing price tables fail closed: repair and bank slot sales are unavailable. World schema v21 stores `gossip_menu_id`, `trainer_type`, `trainer_class`, `trainer_race` and `trainer_spell` from imported vmangos `creature_template` rows. The creature lookup supplies these to trainer and gossip handlers. `NpcServices:NpcTemplates` remains an explicit override. `<refs-root>\vmangos\src\game\Objects\CreatureDefines.h:242,272-275`; `<refs-root>\vmangos\src\game\Objects\Creature.cpp:622,1375-1441`.

World schema v53 adds `npc_vendor_template` and `creature_template.VendorTemplateId`. Fresh import reads both; `refresh --migrate` fills the shared rows and template links in an existing world while preserving its direct vendor rows. `.reload npc_vendor` reads both lists and links again, and `.reload creature_template` refreshes the links. Template rows that fail the vmangos load checks are logged and skipped; direct `npc_vendor` rows get no load-time maxcount/incrtime or cap check, and the vendor window lists at most `MaxVendorItems` (128) entries. A refresh whose dump has a malformed `npc_vendor_template` warns and leaves both the shared stock and the links alone. Run `arcane-db upgrade` first, then `refresh` without `--migrate`. Limited stock remains per creature GUID and item, including shared rows. See [the import area](content-import.md).

`spell_chain.req_spell` is not represented in the rank catalog, so an additional spell prerequisite can be missing; the prev_spell links of talent abilities are supplied by `TalentAbilityRankLinks`. Honor-rank vendor items fail closed until an honor seam exists. The normal asynchronous character save queue persists purchased bank slots with money; durable success is established at the save/flush boundary. Real 1.12.1 client acceptance remains pending.

The NPC content store reads `npc_trainer` rows keyed by creature entry. vmangos also has
trainer-template/`trainer_id` indirection (`<refs-root>\vmangos\src\game\Handlers\NPCHandler.cpp:275-290`);
that content path is not imported yet. A vmangos dump that uses only the indirection needs
its trainer spells materialized into ArcaneCore's `npc_trainer` table before those trainers
offer lessons. Whether the selected content dump uses that path is an open data question.
