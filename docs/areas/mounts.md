# Mounts and riding (mounts-riding lane)

Target: WoW 1.12.1, build 5875. The mount display, speed auras and result packets predate this lane (`docs/areas/locomotion.md`, slices 6 and 8). This lane adds the mount cast and mounted-caster rules. No mount values or code were copied from the read-only reference repositories.

## Runtime behavior

- `SPELL_AURA_MOUNTED` (78) treats its misc value as a creature entry. The world creature template chooses a display, written to the public `UNIT_FIELD_MOUNTDISPLAYID` (`D:\refs\vmangos\src\game\Spells\SpellAuras.cpp:2251-2276`, `D:\refs\vmangos\src\game\Objects\UpdateFields_1_12_1.h:78`). An aura removal clears the field. Mount and dismount results are one `u32`, opcodes `0x16e` and `0x16f` (`D:\refs\wow_messages\wow_message_parser\wowm\world\mount\smsg_mountresult.wowm:29-31`, `D:\refs\wow_messages\wow_message_parser\wowm\world\mount\smsg_dismountresult.wowm:8-10`). The field travels through the existing unit update-object path; no new packet layout is introduced.
- Mount speed uses the existing speed aura ledger: 60% or 100% is the amount of `MOD_INCREASE_MOUNTED_SPEED` (32) from the imported spell, and only the strongest aura of that type contributes. Mounted `MOD_MOUNTED_SPEED_ALWAYS` (130) values multiply each other, while the strongest `MOD_MOUNTED_SPEED_NOT_STACK` (172) competes with that product; the larger bonus multiplies the main increase. Slows apply afterward. Unmounted speed auras (31, 129, 171) do not contribute while mounted (`D:\refs\vmangos\src\game\Objects\Unit.cpp:6959-7061`, `D:\refs\vmangos\src\game\Objects\Unit.cpp:7086-7100`). `UnitSpeed` already implements this and the force-speed acknowledgement path.
- A non-triggered mount cast obeys the spell's `UNDER_WATER_CANCELS` flag: swimming or high liquid while in water returns `ONLY_ABOVEWATER`; shallow water does not. `ONLY_OUTDOORS` and `ONLY_INDOORS` use the map collision outdoor query for players other than GMs. Most dungeons reject mounts, except Zul'Farrak (209), Caverns of Time (269), Zul'Gurub (309) and Ruins of Ahn'Qiraj (509). Area 35 rejects them. Disallowed form IDs reject with `NOT_SHAPESHIFT`; taxi flight rejects a player cast (`D:\refs\vmangos\src\game\Spells\Spell.cpp:5357-5388`, `D:\refs\vmangos\src\game\Spells\Spell.cpp:6373-6392`, `D:\refs\vmangos\src\game\Maps\Map.h:95-100`, `D:\refs\vmangos\src\game\SharedDefines.h:1626-1644`).
- An ordinary, non-triggered spell cast while mounted dismounts and removes the mount aura before its item check. A taxi passenger gets `NOT_ON_TAXI`. Passive, triggered and `ALLOW_WHILE_MOUNTED` spells keep the mount (`D:\refs\vmangos\src\game\Spells\Spell.cpp:5674-5692`). `CMSG_CANCEL_AURA` already removes a cancelable mount aura (`D:\refs\vmangos\src\game\Handlers\SpellHandler.cpp:333-367`; ArcaneCore `SpellSystem.CancelAura`). The generic damage path removes a mount aura when its imported `AuraInterruptFlags` include `DAMAGE`, and cancels a preparing mount spell when its `InterruptFlags` include `DAMAGE_CANCELS`; no universal chance to dismount was added (`D:\refs\vmangos\src\game\Objects\Unit.cpp:660-670`, `D:\refs\vmangos\src\game\Objects\Unit.cpp:900-947`).
- Cast time, recovery and global cooldown come from `SpellInfo`, including a 1.5-second cast when the imported `SpellCastTimes.dbc` row resolves to 1500 ms. The test advances a synthetic 1500 ms mount cast with a controllable clock; it does not force that time on every mount, including class spells (`D:\refs\vmangos\src\game\Spells\Spell.cpp:3431-3441`, `D:\refs\vmangos\src\game\Spells\Spell.cpp:5311-5316`).
- A flight master rejects a mounted player. The scripted taxi start clears a spell mount through the world spell system before the taxi display is applied (`D:\refs\vmangos\src\game\Objects\Player.cpp:17861-17894`).
- Riding is data-led: skill 762, trainer spell effects and item `RequiredSkill`/`RequiredSkillRank`/`RequiredLevel`/`RequiredSpell` are already represented. No synthetic riding tier or additional level gate is applied to the spell itself. The trainer and skill paths are in `docs/areas/skills.md`; item requirements are in `PlayerInventory.CanUseItem` (`D:\refs\vmangos\src\game\Objects\Player.cpp:15164-15217`, `D:\refs\vmangos\src\game\Objects\ItemPrototype.h:453-456`). Paladin and warlock mount spells use the same mounted aura and speed effects when present in imported spell data; their acquisition is handled by spellbook, trainer or quest data rather than a class-specific exception here.

## Limits and integration points

- `CMSG_USE_ITEM` has no world handler in this checkout. A mount item cannot be activated through the client yet, so its item requirements are represented but not enforced on a client mount-item cast. A learned class mount spell does use the spell route. Trainer content and real build-5875 DBC rows were not exercised in this lane.
- Riding terminology needs a data decision: the stated lane rule says not to introduce an Apprentice Riding tier, while the primary vmangos reference explicitly says the shared Apprentice/Journeyman skill was added in patch 1.12 and maps spells 33388/33391 to values 75/150 (`D:\refs\vmangos\src\game\Objects\Player.cpp:15164-15170`, `D:\refs\vmangos\src\game\Objects\Player.cpp:15223-15239`). This lane introduces no tier names or substitute requirement. The imported 1.12 client/DB data should settle trainer display and requirements at integration.
- The shapeshift service currently handles warrior stances only. Druid Cat and Travel Form's live form speed and transformation remain with that service; the mount gate reads its form byte, so it rejects a disallowed form if one has been applied (`D:\refs\vmangos\src\game\Objects\Unit.cpp:5870-5892`). Non-native display models need the CreatureDisplayInfo/Extra/ModelData flags before the display half of that rule is available.
- `SpellInfo` does not carry the reference's required-area override, so a special mount spell with that override will still meet the ordinary map restriction. The outdoor query treats a WMO as outdoors when vmap area data is unavailable. Entering a no-mount map and walking into a forbidden area do not currently recheck an existing aura; the check runs at cast start and landing.
- Capital-city restrictions are driven by the imported area and spell attributes, not by a city-name list. The reference has an explicit area 35 rejection (`D:\refs\vmangos\src\game\Spells\Spell.cpp:6386-6387`). No separate first-aid interaction or capital-wide mount ban was found in the verified mount cast path; this lane does not add one.
- Live 1.12.1 client acceptance remains pending: mount animation/display after `SMSG_UPDATE_OBJECT`, 60% and 100% movement, cast failure texts, Paladin/Warlock spells, and visible dismount after damage or aura cancel. No provider or schema changes were made.

## Verification

Release solution build, the focused mount and taxi tests, the full Game suite (3666 passing), and `NpcServiceWorldTests` (25 passing) passed locally. The tests cover water, form, taxi, map exceptions, normal-cast dismount, direct-display dismount, 1500 ms cast timing, damage interruption and the existing display/speed/result packet behavior. The full World suite had one reproducible failure in `LifePersistenceTests.HealthPowerAndExperience_SurviveARelog` (saved rage restored as 0); the mount changes have no path to its rage restore. Build-5875 client verification and real content import were not run.
