# Deferred trade item enchant settlement

The build-5875 CMSG_USE_ITEM path now defers a single item-template on-use enchant on the partner's non-traded slot. It authorizes the server-resolved item and template index without requiring spellbook knowledge, preserves ordinary eligibility and binding before deferral, and rejects unsupported multi-spell or mixed/random effect shapes. No ordinary cast, charge payment, SpellStart or global cooldown runs during the deferred request.

Final acceptance resolves the cast item by GUID, allowing movement between inventory positions, while requiring the captured entry and selected ItemSpell metadata. Both partners' trade, gold, enchant fields, exact reagent GUID/count selections and cast-item charge/deletion images enter the existing serializable economy settlement. A pure payment is recomputed against the complete live Before image; generic enchant replacements remain restricted to enchant fields. Incoming and outgoing items cannot pay. Conflict/refusal does not publish payment, enchant fields or cooldown. Ordinary pre-request binding is retained on refusal, as in the primary source.

When a cast-item entry is also a reagent, reagent settlement clears the cast-item payment pointer and avoids another charge/deletion, even if a different stack paid. The extra last-charge reagent applies when the spell's required reagent count exceeds one, not merely when the cast item has a stack count above one (vmangos Spell.cpp:7259-7273).

After authoritative commit, publication uses the real partner item GUID with the TradeItem mask. SpellGo uses the cast-item GUID for ordinary item payment, and the player GUID when reagent handling cleared the cast item. Cooldown ownership retains the source entry and selected template cooldown/category values, including zero and minus-one inheritance semantics. The same live plan reference suppresses repeated callbacks; this is not a durable cooldown/packet journal.
