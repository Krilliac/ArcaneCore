## Content and data boundary

ClassicDB z2815 contains 19 Emi, 25 Belnistrasz, 47 Willix and 12 Scarlet trainee `script_waypoint` rows. It also has the six dungeons' `script_texts` rows and Zul'Farrak `dbscripts_on_event` rows 2488 (2 steps) and 2609 (109 steps). The importer now maps only these paths/text ranges and the two events into existing `creature_movement_template`, `creature_ai_texts` and relay tables. A world content refresh from that dump is required before the live world has those rows. The two event ids are stored as relays in the block `RelayScriptCatalog` reserves for event scripts (`EventRelayId`: 2,000,002,488 and 2,000,002,609), avoiding a relay schema change; the importer refuses any real `dbscripts_on_relay` row in that block (see the rework section). The 2609 event's cage-door and faction commands (11/22) have handlers; other commands it uses already had relay handlers.

All 72 script text ids used by these new C# scripts were found in z2815's `script_texts`; Emi's one gossip option is row -3090000 of `gossip_texts`; the importer carries that row into `creature_ai_texts` and her gossip adapter reads it from there (the z2815 string is only the fallback for a world imported before the row was carried).

Known limits against the reference:

- The six dungeons have synthetic map tests and real dump import checks, but no real-client dungeon run. In particular, the escort and boss choreography has not been observed through packets in a running dungeon.
- The Scarlet Ashbringer event starts ClassicDB relay 9001 when Mograine receives spell 28441. Its five source rows use existing relay commands; the full scene still needs packet-level verification.
- Uldaman's `OnCreatureGroupDespawn` custom Annora world state is absent from ArcaneCore's instance hooks.
- Belnistrasz's temporary ritual mobs and Willix's boars use the out-of-combat summon timer. Zumrah now casts spell 10247 at the selected grave through a destination-target creature cast; ClassicDB `spell_template` has two SUMMON_WILD effects (entries 7286 and 7276), so the spell system supplies the count and lifetime. This needs a real spell-content profile and an in-dungeon packet check.
- Scarlet's `ABEffect000::OnCheckTarget` line-of-sight filter for spell 28441 and ScriptDev2's full `FollowerAI` assistance/failure lifecycle for Kernobee do not have dedicated adapters here. The existing generic spell and movement rules may cover part of them, but equivalence has not been verified.
- Instance save strings still live only in memory across a server restart, as recorded in `docs/integration/wave4-20261008.md`; no characters schema version was allocated to this lane.

The source paths above are relative to `D:/refs/mangos-classic/src/game/AI/ScriptDevAI/scripts/`, except the engine's DB event command implementation in `D:/refs/mangos-classic/src/game/DBScripts/ScriptMgr.cpp` (`SCRIPT_COMMAND_OPEN_DOOR`, `SCRIPT_COMMAND_SET_FACTION`). ## Intake fixes (2026-10-08)

Reviewed against mangos-classic ScriptDevAI and rebuilt natively before commit:

- **Thermaplugg bomb faces never spawned walking bombs.** The boss kept its own face timers and treated 0 as "just activated", so a
  3000 ms timer counted down by 50 ms map ticks reached exactly 0 and was reset to 3000 forever. The timers now live in
  `GnomereganInstance` as `sBombFace::m_uiBombTimer` does (`DoActivateBombFace` sets 3000, `DoDeactivateBombFace` 0) and fire on the
  update after reaching 0 (`m_uiBombTimer < uiDiff`). Test `Thermaplugg_ActiveBombFace_SummonsAWalkingBombThreeSecondsAfterItsActivation`
  failed before the fix and passes after.
- **Script AIs for creatures loaded before the instance data attached.** The scripts registered their entry AIs from
  `OnCreatureCreate` with `rebuildExisting: false`, which is right during a grid load (the hook runs before the AI is built) but left
  the template AI on creatures `InstanceManager.AttachInstanceData` reports after an early grid load. They now pass
  `rebuildExisting: creature.AI is not null`. Test `InstanceDataAttachedAfterAGridLoaded_GivesTheAlreadyBuiltCreatureItsScriptAi`
  failed with the old argument.
- **Herod's frenzy emote** `EMOTE_GENERIC_ENRAGED` (-1000003, `boss_herod.cpp`) was not imported; the importer keeps that one generic
  `script_texts` row too.
- **The real-dump test `CreatureBehaviourImportTests.RealClassicDbDump_ImportsAllAiRows` failed** once the dump was supplied: it
  asserted 0 `creature_ai_texts` rows, and the importer now maps 84 ScriptDev2 `script_texts` rows there (counted independently from
  the z2815 dump). The assertion now expects 84. The lane's own report had run the Data project without the dump, so it missed this.
- Zul'Farrak opening `GO_END_DOOR` when the pyramid is DONE is a deviation (in the references Weegli's script blows the door); it is
  now commented as such in `ZulFarrakInstance.SetData`.

2026-10-09 follow-up: the instance now keeps the door shut at pyramid completion and saves a separate end-door state. Weegli Blastfuse's gossip starts the run, summons the imported Explosive Charge 144065, and opens the imported door 146084 only after his retreat point and the charge's spell 13259. A nine-field older instance save loads with the new door state at zero, so Weegli remains necessary; a finished door is restored open on object creation. Focused Game tests cover the phase order, gossip action, charge cast request, interrupted-combat return, death before the blast, missing charge content, and save/load. A read-only imported-world test confirms Weegli, the door, the charge template, explosion spell, and their positions. A bounded loopback test with the build-5875 FactionTemplate DBC and extracted terrain enters map 209, receives and selects Weegli's gossip option, then waits for automatic world-tick movement to open the imported door and save the completed state. Earlier gossip refusals came from a test host with no faction-template catalog. Blast visuals and original-client acceptance remain unverified.

## Review rework (2026-10-08, second round)

Eight reviewer findings, each fixed or answered against mangos-classic ScriptDevAI and ClassicDB z2815:

1. **Scarlet Monastery wipe.** `SetData(TYPE_MOGRAINE_AND_WHITE_EVENT, FAIL)` despawned both bosses before its "both alive" check, so the
   door was never toggled back and the state stayed FAIL; nor did it set the 30 s respawn. It now follows `instance_scarlet_monastery.cpp`
   branch by branch: both alive → `SetRespawnDelay(30, true)` + despawn each, toggle the door, NOT_STARTED; only Whitemane alive → 30 s for
   her, toggle, FAIL; only Mograine alive → despawn him (no override), FAIL. `SetRespawnDelay(d, true)` is the new one-shot
   `Creature.RespawnDelayOnceSeconds`, consumed by the death that schedules the respawn (`TakeRespawnDelaySeconds`, used by both
   `CreatureMapSystem` death paths). Tests: `ScarletMonasteryEncounterTests.Wipe_*` (respawn at 30 s, not the spawn's 120 s).
2. **Mograine died twice.** `OnLethalDamage` now runs only while death prevention is on (`!_healed`, `InvincibilityHpThreshold != 0`):
   after Lay on Hands the killing blow kills and the event, door and Whitemane's intro are left alone. Deviation, commented: with no
   living Whitemane the prevention is dropped instead of leaving him at 1 hp for good. Test `Mograine_AfterLayOnHands_*`.
3. **Aggro on sight.** New base `ScriptedAI` (Creatures/AI): `AggroesOnSight` true, as ScriptDev2 `ScriptedAI::MoveInLineOfSight`.
   Doan, Herod, Thermaplugg, Mograine, Whitemane, Archaedas and Zum'rah derive from it. Whitemane (passive react state) and Archaedas
   (unselectable until awakened) still do not pull, through `CanInitiateAttack`. Tests: `ScriptedBosses_AttackAHostilePlayerOnSight`
   (Herod, Doan, Mograine), `Whitemane_StaysPassiveOnSight`, `Thermaplugg_AggroesOnSight_*`.
4. **Reset on evade.** `ScriptedAI` calls `Reset()` from `OnRespawn` and `OnEvade` (ScriptDev2 `EnterEvadeMode` ends with `Reset()`).
   Thermaplugg's Reset keeps the summoned-bomb list for `JustReachedHome`; Zum'rah's Reset leaves his hostile turn alone (respawn still
   restores it, an existing commented deviation); Mograine and Whitemane reset only at NOT_STARTED and otherwise fail the event, as their
   `EnterEvadeMode` overrides do. Tests: `HerodAndDoan_ForgetTheirFrenzyAndBubbleWhenTheyEvade`, `Thermaplugg_*_AWipeSendsHimBackToPhaseOne`,
   `Archaedas_AfterAWipe_IsFrozenAndUnselectableAgain_AndTheNextAltarUseReplaysTheAwakening`.
5. **Snufflenose gopher.** `SummonService.Guardians` no longer replaces a guardian's map script AI with `PetAI` (vmangos `selectAI`
   asks the script first). `SnufflenoseGopherAi` is now a ScriptedPetAI: it keeps an inner `PetAI` for following and defending
   (`IScriptedPetAi`; `PetAI.Of` lets `PetMapSystem` and `PetController` reach it) and only takes over while walking to a tubber (LOS
   checked, follow flags cleared so it returns to its owner). Spell 8283 has a DUMMY at TARGET_SCRIPT (38) and this spell system has no
   `spell_script_target`, so `SnufflenoseCommandSpell` (OnCast) finds the nearest living 4781 within the spell's 30 yd as TARGET_SCRIPT
   would. Test `SnufflenoseGopherProductionTests` summons through the real spell 6918 shape (SUMMON_GUARDIAN 4781) and the real summon service.
6. **World adapter coverage.** The routing moved to `Game/Instances/Scripts/DungeonScriptHooks.cs` (quest accept for Willix, Belnistrasz
   and Kernobee; Emi's gossip wrapper; cathedral and Antu'sul triggers; altar spells 11568/10340 and unlocking 10738 with relay 2609);
   `DungeonScriptFeature` only subscribes it. `DungeonScriptHooksTests` (7) run every hook against real instance maps;
   `GnomereganEncounterTests` covers the wrapper chain; `DungeonScriptFeatureTests.StartedWorld_SubscribesTheQuestGossipSpellAndAreaTriggerHooks`
   checks the wiring in a started world (QuestAccepted handler, `EmiGossipScript` chain, spell observer, area-trigger listener).
7. **Minor fidelity.** Doan polymorphs a random threat entry below the top (`SelectAttackingTarget(ATTACKING_TARGET_RANDOM, 1)`).
   Archaedas wakes the targets the spells would take: 7076 within 100 yd (SpellRadius 12) for 10252, two random 10120 within 100 yd for
   10258 (MaxAffectedTargets 2, `FilterTargetMap` SCHEME_RANDOM); the spell system has no TARGET_ENUM_UNITS_SCRIPT_AOE_AT_SRC_LOC, so the AI
   applies it (test `Archaedas_WakesTheGuardiansAndTwoVaultWardersWithin100Yards`). Zum'rah's intro now needs line of sight (not testable
   without collision data: static reasoning only). Emi's menu text id 0 already means the creature's own gossip text
   (`QuestNpcServices.SendScriptedGossip`: `NpcTextId != 0 ? NpcTextId : GossipTextId(npc)`), so that point was not a defect; her option
   is now read from `gossip_texts` -3090000, which the importer carries into `creature_ai_texts` (the real-dump AI text count is now 85).
   Her select also re-checks the Grubbis state as `GossipSelect_npc_blastmaster_emi_shortfuse` does. The relay SET_FACTION temp flags
   are unchanged (z2815 event 2609 only uses flag 0).
8. **Relay id namespace.** Event scripts now live in a reserved block, `RelayScriptCatalog.EventRelayIdOffset` = 2,000,000,000
   (`EventRelayId(2609)` = 2,000,002,609; still inside int range), far above any `entry * 100 + n` relay id (z2815 tops out at
   1,574,201). The importer refuses, with a warning, any real `dbscripts_on_relay` row in that block. Tests:
   `Importer_RefusesARealRelayInTheBlockReservedForEventScripts_InEitherOrder`, `EventRelayBlock_*`, and the real-dump test asserts no
