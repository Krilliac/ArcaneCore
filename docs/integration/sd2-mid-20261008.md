## Content and data boundary

ClassicDB z2815 contains 19 Emi, 25 Belnistrasz, 47 Willix and 12 Scarlet trainee `script_waypoint` rows. It also has the six dungeons' `script_texts` rows and Zul'Farrak `dbscripts_on_event` rows 2488 (2 steps) and 2609 (109 steps). The importer now maps only these paths/text ranges and the two events into existing `creature_movement_template`, `creature_ai_texts` and relay tables. A world content refresh from that dump is required before the live world has those rows. The two event ids receive relay ids 1002488 and 1002609, avoiding a relay schema change. The 2609 event's cage-door and faction commands (11/22) have handlers; other commands it uses already had relay handlers.

All 72 script text ids used by these new C# scripts were found in z2815's `script_texts`; Emi's one gossip option is row -3090000 of `gossip_texts` and is carried directly in her gossip adapter.

Known limits against the reference:

- The six dungeons have synthetic map tests and real dump import checks, but no real-client dungeon run. In particular, the escort and boss choreography has not been observed through packets in a running dungeon.
- The Scarlet Ashbringer event starts ClassicDB relay 9001 when Mograine receives spell 28441. Its five source rows use existing relay commands; the full scene still needs packet-level verification.
- Uldaman's `OnCreatureGroupDespawn` custom Annora world state is absent from ArcaneCore's instance hooks.
- Belnistrasz's temporary ritual mobs and Willix's boars use the out-of-combat summon timer. Zumrah now casts spell 10247 at the selected grave through a destination-target creature cast; ClassicDB `spell_template` has two SUMMON_WILD effects (entries 7286 and 7276), so the spell system supplies the count and lifetime. This needs a real spell-content profile and an in-dungeon packet check.
- Scarlet's `ABEffect000::OnCheckTarget` line-of-sight filter for spell 28441 and ScriptDev2's full `FollowerAI` assistance/failure lifecycle for Kernobee do not have dedicated adapters here. The existing generic spell and movement rules may cover part of them, but equivalence has not been verified.
- Instance save strings still live only in memory across a server restart, as recorded in `docs/integration/wave4-20261008.md`; no characters schema version was allocated to this lane.

The source paths above are relative to `D:/refs/mangos-classic/src/game/AI/ScriptDevAI/scripts/`, except the engine's DB event command implementation in `D:/refs/mangos-classic/src/game/DBScripts/ScriptMgr.cpp` (`SCRIPT_COMMAND_OPEN_DOOR`, `SCRIPT_COMMAND_SET_FACTION`). The reference tree and the ClassicDB dump were read only.

## Intake fixes (2026-10-08)

Reviewed against mangos-classic ScriptDevAI and rebuilt natively before commit:

- **Thermaplugg bomb faces never spawned walking bombs.** The boss kept its own face timers and treated 0 as "just activated", so a
  3000 ms timer counted down by 50 ms map ticks reached exactly 0 and was reset to 3000 forever. The timers now live in
  `GnomereganInstance` as `sBombFace::m_uiBombTimer` does (`DoActivateBombFace` sets 3000, `DoDeactivateBombFace` 0) and fire on the
  update after reaching 0 (`m_uiBombTimer < uiDiff`). Test `Thermaplugg_ActiveBombFace_SummonsAWalkingBombThreeSecondsAfterItsActivation`
  failed before the fix and passes after.
- **Script AIs for creatures loaded before the instance data attached.** The scripts registered their entry AIs from
  `OnCreatureCreate` with `rebuildExisting: false`, which is right during a grid load (the hook runs before the AI is built) but left
  the template AI on creatures `InstanceManager.AttachInstanceData` reports after an early grid load. They now pass
  `rebuildExisting: creature.AI is not null`. Test `InstanceDataAttachedAfterAGridLoaded_GivesTheAlreadyBuiltCreatureItsScriptAi`
  failed with the old argument.
- **Herod's frenzy emote** `EMOTE_GENERIC_ENRAGED` (-1000003, `boss_herod.cpp`) was not imported; the importer keeps that one generic
  `script_texts` row too.
- **The real-dump test `CreatureBehaviourImportTests.RealClassicDbDump_ImportsAllAiRows` failed** once the dump was supplied: it
  asserted 0 `creature_ai_texts` rows, and the importer now maps 84 ScriptDev2 `script_texts` rows there (counted independently from
  the z2815 dump). The assertion now expects 84. The lane's own report had run the Data project without the dump, so it missed this.
- Zul'Farrak opening `GO_END_DOOR` when the pyramid is DONE is a deviation (in the references Weegli's script blows the door); it is
  now commented as such in `ZulFarrakInstance.SetData`.

7,104 passed, 11 skipped (focused instance and relay set 108 passed); Data tests with `ARCANECORE_CLASSICDB_DUMP` set 1,297 passed,
