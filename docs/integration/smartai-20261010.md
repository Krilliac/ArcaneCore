# SmartAI (w18, slice 1)

Data-driven creature AI in the AzerothCore `smart_scripts` format, modelled on AzerothCore
`src/server/game/AI/SmartScripts` (SmartAI.cpp, SmartScript.cpp, SmartScriptMgr.h/.cpp). It is re-implemented, and no code is copied.

## Where it sits

The AI selection order is unchanged (`CreatureAiFactory`, vmangos/cmangos FactorySelector):

1. **C# scripts first.** An instance or raid script (`RaidBossAI.Create`, the per-instance registries) or a registered
   entry script (`RegisterEntryScript`, a ClassicDB `ScriptName`) always wins. A creature with a C# script never runs
   its SmartAI or EventAI rows, so nothing runs twice. This is the same rule cmangos uses for ScriptName over AIName.
2. **AIName next.** `EventAI` / `GuardEventAI` run `creature_ai_scripts` (cmangos format, everything ClassicDB ships).
   `SmartAI` (new) runs `smart_scripts`. A template has exactly one AIName, so one creature never runs both engines.
3. **Default.** GuardAI, implicit EventAI (option), ReactorAI or AggressorAI, as before.

Use EventAI for ClassicDB content. Use SmartAI for new hand-authored or ported (AzerothCore/TrinityCore) content, since
it has richer targeting, links, timed events and phases. Use C# for encounters that need state across creatures or the
instance. ClassicDB z2815 has no `smart_scripts` table, so the table is empty after an import, and no creature says
`AIName = 'SmartAI'` until rows and the AIName are set by hand.

`CreatureSmartAI` is an `AggressorAI`. Victim choice, chase and melee are the aggressor's, and the rows add behaviour
on top, as AzerothCore SmartAI does over its base movement.

## Table (world schema 48)

`smart_scripts` uses AzerothCore's column set: `entryorguid, source_type, id, link, event_type, event_phase_mask,
event_chance, event_flags, event_param1-6, action_type, action_param1-6, target_type, target_param1-4, target_x/y/z/o,
comment`. The key is (entryorguid, source_type, id, link). A negative entryorguid is a spawn guid, and its rows
replace the entry's rows (AzerothCore SmartAIMgr::GetScript). Slice 1 loads only `source_type` 0 (creature). Game
objects (1), area triggers (2) and timed action lists (9) are later slices. Numbering is AzerothCore's, so ported rows
need no translation.

## Semantics kept from AzerothCore

- **Phases.** Phases run 0-12. A nonzero `event_phase_mask` needs bit (phase - 1), so phase 0 matches only mask 0.
  The phase resets to 0 on reset.
- **Timers.** The update events start on (param1, param2) and repeat on (param3, param4). HEALTH_PCT is checked
  every update and uses (param3, param4) as its repeat. Cooldowns (SPELLHIT param3/4) make the event inactive until
  they run out.
- **Flags.** NOT_REPEATABLE (0x01) runs once until reset, DONT_RESET (0x100) keeps the timer over a reset, and
  DEBUG_ONLY (0x80) rows are not loaded.
- **Chance and links.** The chance (1-99) is rolled per run, and 0 or 100 always runs. A failed roll skips the action
  and its link. `link` runs the SMART_EVENT_LINK row with that id, with the same invoker.
- **Casts.** Cast flags INTERRUPT_PREVIOUS, TRIGGERED, AURA_NOT_PRESENT and THREATLIST_NOT_SINGLE are honoured,
  and the third param (triggerFlags) nonzero also triggers the cast. A timed cast without INTERRUPT_PREVIOUS waits
  while the creature is casting.
- **Timed events.** CREATE_TIMED_EVENT stores an UPDATE event that fires TIMED_EVENT_TRIGGERED with its id. It is
  removed after one run when it has no repeat.
- **Hooks.** OnRespawn resets. Reaching home resets, then raises REACHED_HOME. Aggro, death, evade and spellhit pass
  their unit as the invoker.

## 1.12 deviations in slice 1

- **TALK.** `action_param1` is a `broadcast_text` id (positive `creature_ai_texts`/broadcast lookup), not a
  `creature_text` group, because 1.12 has no `creature_text`. The first target, or else the invoker, is `$N`.
- **SUMMON_CREATURE.** The duration (param3) is honoured as a timed out-of-combat despawn, but the summon type
  (param2) is not, and the cmangos summon timer rules apply. Param4 (attackInvoker) attacks the invoker.
- **MOVE_TO_POS.** It moves to `target_x/y/z` (POSITION) or to the first target plus that offset, and runs in combat.
  The transport and controlled params are ignored.
- **Not yet supported.** Conditions (`conditions` source 22) are not checked. Charm gating (WHILE_CHARMED) does not
  exist yet.
