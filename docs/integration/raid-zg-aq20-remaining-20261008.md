## Remaining limits

- **Host EventAI threat order (host gap, outside this lane; found while writing the Gri'lek test):** `ThreatList.Entries` re-sorts when it is read after a change. Inside one EventAI event, the threat list is therefore re-sorted between actions. In cmangos `ThreatManager::getThreatList()` stays in the old order until the next `ThreatContainer::update`, so `SelectAttackingTarget(ATTACKING_TARGET_RANDOM, 1)` still excludes the old top. Gri'lek's 1508201 gives the same result in both orders as long as the tank is still top after halving. If the second player had more than half the tank's threat, the host would re-sort after the -50 percent, could pick the old tank as "not top", and would raise his threat by half. cmangos would raise the other player's threat instead. Any EventAI row that changes threat and then uses a threat-order target in the same event has this shape. The Gri'lek test uses threat values where both orders agree. A fix belongs to `EventAiContext` (take the threat order once per event), not to this lane.
