## Fixes at merge time

Every PR above was a draft, so none of them had run hosted CI. The first full local gate after the merges failed in four
places, all from the PRs themselves rather than their interaction; each is fixed in its own commit.

* **CI matrix (065c6b0c).** #86 ran the per-suite tests as a multi-line `run: |` loop, so `ContributingGuideTests` read `|` as
  the test command (both CI-command tests failed). Each suite is now a solution filter of `ArcaneCore.slnx`
  (`tests/ci/{Game,World,Data,Rest}.slnf`) run by one `dotnet test tests/ci/${{ matrix.suite }}.slnf ...` line. The check names
  `test (Game)`, `test (World)`, `test (Data)`, `test (Rest)` are unchanged. New
  `TheCiSuiteFilters_CoverEveryTestProjectExactlyOnce` fails when the filters drop or double a test project (checked by removing
  MockClient.Tests from `Rest.slnf`). `contributing.md` describes the split.
* **Mock client (503b929b).** #84 seeds the vmangos Warden scans into every world database through `WorldDbInitializer`, so
  synthetic quest seeding refused every fresh database ("table 'warden_checks' already has rows"): 142 MockClient tests and the
  self-test failed. `warden_checks` joins the initializer-seeded baseline tables.
* **AH bot (3f12344f).** `AuctionBotCustodyDataModule` did not implement `ICharacterDataCleanup` (`CharacterDeletionTests`,
  `GameEventStatusStoreTests`); the ledger is keyed by operation, so the cleanup is a documented no-op. `EfAuctionBotCustodyStore`
  filtered with `string[].Contains`, which C# 14 binds to `MemoryExtensions.Contains(ReadOnlySpan<T>)` and EF Core cannot evaluate
  (`AuctionBotFeatureTests.Reserved_rows_from_before_a_restart_are_rechecked_against_the_operation_ledger`); it uses a `List<string>`
  like the other stores.
* **Hot code (18339da3).** `HotCodeRefresh` added the roots of every discovered `ICommandGroup` without asking `IsEnabled`, so a
  refresh would have switched `.ahbot` on with `AuctionHouseBot:Enabled` off
  (`RefreshCoreTests.OnTheRealWorld_ACommandAndAnOpcodeAddedAtRuntime_WorkWithoutARestart` saw 2 new roots). The refresh now takes the
  host's services and filters as `ChatCommands.Build` does at startup. New `ADisabledCommandGroup_IsNotAddedByARefresh`.
* **Economy validation (1170cdf8), from the merge review.** Validation refused a duplicate `MintEscrowItem` GUID but not a repeated
  `CreateEscrowItem`, or one beside a mint, which reached the store as two tracked rows. Both kinds share one check now.

An independent review of every hand resolution and of semantic overlaps git does not flag (GM command roots, configuration
sections, opcode handlers, DI registrations, script/AI factory keys, spell effect registrations) found no blocking issue.
