# Operator debug tooling (2026-10-08)

The new `Diagnostics:PacketCapture` section defaults to disabled. An Administrator can set `Enabled=true`, then use `.debug capture on <player>` and `.debug capture off <player>` on an online character. Each explicit `on` creates a new PKT 3.1 trace in `Directory` (default `packet-captures`); a trace stops at `MaxBytes` (default 64 MiB) or disconnect. The command can explicitly target a managed bot; bots are never captured automatically. Trace payloads are plaintext and can include private chat and other player data. Filenames are generated independently of player names.

`arcane-sniff decode <file>` reads build-5875 PKT 3.1 traces and prints timestamp, direction, opcode name, payload size, and decoded fields. It uses the vendored `WowWorldMessages.Vanilla` server/client readers in `tests/ThirdParty/WowWorldMessages`, with a byte offset on decode failure. Opcodes the oracle cannot read (the `allowlisted` rows of the wire-oracle histogram, such as `SMSG_MESSAGECHAT`) print as `decode failed at byte 0: ...` with their size; the exit code is 1 when any record failed. The World daemon has no dependency on those readers. The existing third-party notice now records the tool's use of that MIT vendored source; no new upstream code was copied.

`arcane-db dbc dump <File> [--id N] [--json]` reads a build-5875 WDBC file without opening any server database. `File` may be an explicit path or a name below `ClientData:DbcDirectory`. The field names, physical offsets, widths, arrays, and foreign-key annotations come from `ClientDbcLayouts.Dbd.g.cs` (WoWDBDefs commit `e3df370`; see `THIRD_PARTY_NOTICES.md`). Output is one row per line; `--id` needs a 32-bit `ID` field. The reader checks the header and record/string bounds before printing.

The generated [opcode reference](../reference/opcodes.md) combines `WorldOpcode.g.cs`, the live `WorldServiceCollectionExtensions.BuildOpcodeTable()` registry, and the committed [wire-oracle histogram](wire-oracle-histogram-20261008.tsv). The histogram represents the wave 8 test run, not live traffic. The registry has no explicit ignored-opcode registration, so CMSG rows are currently `handled` or `unhandled`; `MSG_` opcodes travel both ways and fill both columns (vmangos `src/game/Server/Protocol/Opcodes.cpp` registers client handlers for them); session-level `CMSG_PING` and `CMSG_AUTH_SESSION` are counted as handled.

## Format and behavior sources

- PKT 3.1 header and record order: `D:/ArcaneCore-lanes/_refs/csharp-cores/WowPacketParser/WowPacketParser/Loading/BinaryPacketReader.cs`, `ReadHeader` and `Read` (version 0x301, build, locale, 40-byte key slot, Unix start time, start tick, direction, connection index, record tick, optional size, record size, 32-bit opcode). Only format facts were used; no GPL source was copied.
- World header sizes and encryption boundary: [wowdev World Packet](https://wowdev.wiki/World_Packet) and vmangos `src/game/Server/WorldSocket.cpp`, `WorldSocket::handle_input_header` / `WorldSocket::handle_input_payload`. Captures start after the authenticated session is selected; the existing `WorldSession.ReadLoopAsync` and `WorldSession.Send` strip/decrypt or assemble transport headers before calling the trace writer.
- PKT 3.1 struct field names are independently described by [TrinityCore PacketLog.cpp](https://master.trinitycore.net/da/d3f/packetlog_8cpp_source). This implementation was written against the WPP reader and the local round-trip tests, without copying its source.

No ClassicDB rows or schema step are needed. The capture/decode test is a synthetic packet round trip. Real-client traces and consumer compatibility with external sniff tools remain unverified.
