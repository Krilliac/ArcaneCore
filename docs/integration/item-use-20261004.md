# Item use integration (2026-10-04)

The build-5875 `CMSG_USE_ITEM` path is wired through the ordinary spell pipeline.
The request is decoded as `u8 bag`, `u8 slot`, `u8 spell index`, then the
build-5875 `SpellCastTargets` block. Payloads with trailing bytes are rejected;
the TBC cast-count and item-GUID trailer is not accepted for this client build.

The world handler resolves the live inventory object, validates the selected
template spell as an on-use spell, applies ownership/use/equipped checks, and
retains the item instance through delayed casts. `SMSG_SPELL_START` and
`SMSG_SPELL_GO` carry the cast item GUID. A cast whose item moved or was deleted
is cancelled before costs are applied. Successful effects settle item charges
after SpellGo; negative-charge expendables remove one item from the stack.
All template on-use spells are dispatched in order, with only the first cast
normal and later casts triggered, matching `Player.cpp:7362-7403`. Item
cooldown/category values override spell defaults in memory and use the existing
persisted server cooldown duration rows. The item-use feature rejects active
trade offers, held/transit/logout/settlement states, empty charges, invalid
shapeshift use, and full-health/full-power consumables; mixed heal/energize
consumables remain usable when either resource is restorable. This checkout has
no remote-control/self-mover producer beyond active mover GUID validation, so
the vmangos `IsSelfMover` guard remains an explicit integration limitation.

Persisted cooldown owner metadata is still pending: current relog state retains
durations and category IDs but does not yet retain the item entry/effective item
category association needed to reconstruct `SMSG_INITIAL_SPELLS` exactly. See
`work/item-use-lane/item-cooldown-next.md` for the proposed owner-row contract.

Ground truth: vmangos `SpellHandler.cpp:36-139`, `Player.cpp:7362-7403`,
`Spell.cpp:4991-5049,7109-7175`, and `Player.cpp:22139-22214`, plus
gtker/wow_messages `world/item/cmsg_use_item.wowm` (1.12). Automated full-suite
status, real-client acceptance, and proprietary build-5875 content validation
remain coordinator-owned verification items. Other item features such as
on-equip/proc/set spells, loot containers, enchantments, and random properties
remain outside this integration slice.
