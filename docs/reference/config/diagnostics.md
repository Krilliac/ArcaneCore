# Diagnostics options

27 options. Set them in the daemon's `.conf` file or `appsettings.json`. Full reference: [configuration.md](../configuration.md). All areas: [index](README.md).

Daemon says which server reads it. Reload says whether `.reload config` applies it.


## `Diagnostics`

| Option | Type | Default | Allowed | Daemon | Reload | What it does |
|---|---|---|---|---|---|---|
| `BeepOnException` | bool | `false` | true \| false | Both, Gateway | start | Emit a short console beep when the crash hooks or the fault ledger log an exception in an interactive console session (`Environment.UserInteractive` and standard error not redirected), rate-limited to at most one beep per second so a fault storm cannot stall or flood the terminal. Default off. |
| `BeepOnStartup` | bool | `false` | true \| false | Both, Gateway | start | Emit a short console beep when the daemon finishes starting in an interactive console session (`Environment.UserInteractive` and standard output not redirected), matching the classic MaNGOS `BeepAtStart` cue. Never beeps under a service, test runner or redirected output. Default off. |
| `BreakOnInvariant` | bool | `false` | true \| false | Both, Gateway | start | Stop in the debugger on a failed invariant (`Debugger.Break`). Only acts when a debugger is attached, so it is safe to leave on in a development configuration; default off, because an unattended process must never wait for a debugger prompt. |
| `CrashDialog` | bool | `false` | true \| false | Both, Gateway | start | Show a dialog (a Win32 message box) when the process is about to end because of an unhandled exception, an unobserved task exception under an `OnUnobservedTask` policy that terminates, or a world tick hang the watchdog ends. It names the exception, its message and full stack with inner exceptions, the daemon and version, thread, time, fault-ledger site and signature, and the crash report file (a `crash-report.*.txt` file written next to the daemon), crash journal and log file. It appears after the crash is logged and recorded, and the exit policy runs when it is closed. Only a Windows console session with no redirected standard stream, outside CI, opens one; a service, test run, redirected or non-Windows process is unaffected. Default off: an unattended process must never wait on a dialog. |
| `CrashDump:Directory` | string | `(empty)` | text | Both, Gateway | start | The directory the dump files are written to, named `&lt;daemon&gt;-&lt;pid&gt;-&lt;yyyyMMdd-HHmmss&gt;.dmp` (UTC). Empty (default) means `dumps` beside the log file (the resolved `Logging:ArcaneCore:File:Path`, so `logs/dumps` by default, the directory `.debug dump` uses), or `dumps` in the daemon's own directory when file logging is off. Created on the first dump, readable by the daemon's account only on Linux and macOS. |
| `CrashDump:FullMinFreeGB` | int | `16` | a whole number of GiB, 0 or more; 0 never falls back for space | Both, Gateway | start | Free space, in GiB, the dump volume must have for a Full dump; below it Full falls back to Heap. Default 16, the launcher's threshold (`tools/ops/live/LiveDiagnostics.ps1`). 0 never falls back for space. |
| `CrashDump:MaxFiles` | int | `5` | a whole number, 0 or more; 0 keeps every file | Both, Gateway | start | How many of this feature's dump files are kept in the directory: after a dump is written the oldest beyond this count are deleted. Only files named by the pattern above are touched. 0 keeps every file. Default 5. |
| `CrashDump:Mode` | CrashDumpMode | `Full` | Off \| Mini \| Heap \| Full | Both, Gateway | start | What to write: `Off`, `Mini`, `Heap` or `Full`. Default `Full`: it only acts when the process is already crashing, so it changes nothing for a healthy server. A failure of the chosen type falls back Full, Heap, Mini and is logged. Values: `Off`, `Mini`, `Heap`, `Full`. |
| `CrashDump:TimeoutSeconds` | int | `120` | a whole number of seconds, 1 to 3600 | Both, Gateway | start | How long the daemon waits for its own diagnostics server to start a dump before it gives up and ends the process anyway; it bounds an unresponsive server, not the length of a dump. The runtime suspends the waiting thread too, so a slow dump can outlast it: a file that is still growing is waited for, up to three times this value in total (a Full dump of a 7 GB process takes about a minute). A timeout, or an unreachable diagnostics endpoint (`DOTNET_EnableDiagnostics=0`), is not retried with a smaller type; a type the runtime refuses is. While it dumps the daemon publishes the heartbeat state `dumping`, which supervisors honour for the announced maximum (three times this) plus a minute, bounded by their own cap (`Cluster:Supervisor:DumpGraceSeconds`, default 420; raise it with this value). Default 120. Checked at start (1 to 3600) so the product cannot overflow. |
| `FaultDialog` | bool | `false` | true \| false | Both, Gateway | start | Also show a dialog the first time each fault signature is caught and survived (the fault ledger, `.server faults`), on a background thread so the faulting thread never waits, at most one open at a time (faults while one is open are only logged). Needs the same interactive Windows console session as `CrashDialog`; takes effect once the host has started. Default off: a fault storm of new signatures still means one box after another. |
| `FaultLogLimit` | int | `10` | a whole number, -2147483648 to 2147483647 | Both, Gateway | start | How many occurrences of one fault (an exception type thrown from one place, caught at one of the server's catch-and-log sites) are logged in full. After that the site logs that fault at most once a minute, with "(N more since)"; every occurrence is still counted in the fault ledger (`.server faults`, the `arcanecore_faults_total` metric). 0 logs the first occurrence and then once a minute. Default 10. |
| `FaultMaxSignatures` | int | `512` | a whole number, -2147483648 to 2147483647 | Both, Gateway | start | How many distinct faults the fault ledger keeps. A fault beyond the cap is counted into one overflow entry, never dropped. Default 512; a lower value bounds memory on a server that throws a new exception signature per request. |
| `FirstChanceExceptions` | bool | `false` | true \| false | Both, Gateway | start | Log exceptions at the moment they are thrown (`AppDomain.FirstChanceException`), before any handler sees them, at Debug level. The log is deduplicated per exception type and throw site, rate limited and capped, so a hot throw site cannot flood it; it is not a complete record of every throw. A development aid for finding swallowed exceptions; it is honoured only by a Debug build of the Kernel (the hook is compiled out of Release), where a Release daemon logs once that the key is ignored. Default off: the hook runs on every throw, caught or not. |
| `InvariantLogLimit` | int | `10` | a whole number, -2147483648 to 2147483647 | Both, Gateway | start | How many failures of one invariant (one call site) are written to the log; later failures of that site are only counted (the counters are part of every crash report). 0 logs none, every failure is still counted. Default 10: a hot-path check that fails per packet cannot flood the log. |
| `OnInvariant` | InvariantPolicy | `Continue` | Continue \| FailFast | Both, Gateway | start | What a failed `Invariant.Check` (the release-mode check) does after it is logged and counted. `Continue` (default): the caller goes on with its own fail-closed handling (refuse the packet, drop the connection, throw). `FailFast`: the process aborts at once with the message, as the mangos `MANGOS_ASSERT` macro does in every build. Debug-build `Invariant.Assert` throws `InvariantViolationException` under `Continue` and aborts under `FailFast`. Values: `Continue`, `FailFast`. |
| `OnUnhandled` | UnhandledExceptionPolicy | `FailFast` | FailFast \| Exit | Both, Gateway | start | What ends the process after an unhandled exception (`AppDomain.UnhandledException`): the report is always written first. `FailFast` (default): `Environment.FailFast`, which is what the runtime does on its own; the process aborts (exit status 134, SIGABRT, on Linux; 0x80131623 / Watson on Windows). `Exit`: `Environment.Exit(70)` (`ExitCodes.UnhandledException`, sysexits EX_SOFTWARE), an exit code a supervisor can match. Under both, the daemon writes a dump of itself first (`Diagnostics:CrashDump`); the runtime's own `DOTNET_DbgEnableMiniDump=1` dump covers a FailFast too, and then this one is skipped. Values: `FailFast`, `Exit`. |
| `OnUnobservedTask` | UnobservedTaskPolicy | `Log` | Log \| Exit \| FailFast | Both, Gateway | start | What an exception a faulted `Task` nobody awaited does when the finalizer finds it (`TaskScheduler.UnobservedTaskException`). `Log` (default): the report is written and the exception marked observed, which is the .NET runtime's own behaviour (since .NET 4.5) made visible. `Exit` and `FailFast` end the process as `OnUnhandled` describes. Values: `Log`, `Exit`, `FailFast`. |

## `Diagnostics:PacketCapture`

| Option | Type | Default | Allowed | Daemon | Reload | What it does |
|---|---|---|---|---|---|---|
| `Directory` | string | `packet-captures` | text | World | start | Directory for new traces; generated filenames do not include player input. |
| `Enabled` | bool | `false` | true \| false | World | start | Permit an Administrator to start a session capture. Default false. |
| `MaxBytes` | long | `67108864` | a whole number, -9223372036854775808 to 9223372036854775807 | World | start | Maximum bytes in one trace, including its header; a full trace stops automatically. A trace also stops when the disk writer falls 8192 records behind. Records are written by a background writer and the file is finished asynchronously after a stop; the server drains open traces at shutdown. |

## `Diagnostics:SessionTrace`

| Option | Type | Default | Allowed | Daemon | Reload | What it does |
|---|---|---|---|---|---|---|
| `BurstLines` | int | `200` | a whole number, -2147483648 to 2147483647 | World | start | Lines one trace may write in a burst (the capacity of its token bucket, full when the trace starts). Default 200. |
| `DefaultMinutes` | int | `30` | a whole number, -2147483648 to 2147483647 | World | start | Minutes a trace runs when `on` is given no minutes. Clamped to 1 to `MaxMinutes`. Default 30. |
| `Enabled` | bool | `true` | true \| false | World | start | Permit a Game Master to start session traces. When false, `.debug trace session ... on` is refused and nothing is ever written. Default true. |
| `LinesPerSecond` | int | `50` | a whole number, -2147483648 to 2147483647 | World | start | Lines per second one trace may write on average (the refill rate of its token bucket); lines over the budget are dropped and counted. Default 50. |
| `MaxMinutes` | int | `240` | a whole number, -2147483648 to 2147483647 | World | start | Longest a trace may run in minutes; a longer request is clamped and the reply says so. Default 240. |
| `MaxTracedCharacters` | int | `16` | a whole number, -2147483648 to 2147483647 | World | start | Most characters that can be traced at the same time; turning a further one on is refused. Re-tracing a traced character is not a further one. Default 16. |
| `SlowHandlerMicroseconds` | int | `1000` | a whole number, -2147483648 to 2147483647 | World | start | A packet handler is logged (`handled` line) only when it ran longer than this many microseconds. Default 1000. |
